# 레퍼런스 4컷 실험 · 롤백 우선

기본값은 `STUDIO_SCENE_MODE=single`입니다. 이 변경은 아직 실제 Cloud 이미지 품질이 검증된 기본 경로가 아닙니다.
현재 Git 연동 Vercel 배포는 저장소의 `vercel.json.env.STUDIO_SCENE_MODE=storyboard4`로 실험을 켭니다.
이 값은 비밀이 아닌 기능 플래그이며 OpenAI·Comfy·Turso 키는 저장소에 넣지 않습니다.
main에 푸시한 뒤 자동 배포가 완료되면 `/health`의 `studio_scene_mode`가 `storyboard4`인지 확인합니다.
실험을 켜려면 서버 환경변수를 `STUDIO_SCENE_MODE=storyboard4`로 바꾸고 재시작합니다.
FE 변경이나 DB 마이그레이션은 없습니다. 새 장면 생성에만 영향을 주고 기존 그림을 교체하지 않습니다.

## 처리

1. 기존과 동일하게 GPT가 고정 10종에서 인물을 선택하고 얼굴 크롭을 적용·고정합니다.
2. 아직 그림이 없는 장면 카드를 문서 순서대로 최대 4개 예약합니다. 기준 인물의 합집합이 3명을 넘기 전에 묶음을 나눕니다.
3. 각 카드의 글·원문 근거·주장/판단/결정 구분을 GPT 구조화 출력으로 설계합니다.
   컷마다 인물·표정·위치·행동(`characters`), 상황(`situation`), 오브젝트·상태·위치(`objects`)를 필수로 분류합니다.
   서버가 partyId를 Picture 번호로 연결해 각 컷의 세 항목을 모두 프롬프트에 포함합니다.
   인물 레퍼런스 번호는 묶음 전체에서 통일합니다. 실제 입력은 얼굴이 아닌 한 명짜리 기본 포즈 원본입니다.
4. Qwen Edit 2511 FP8, **50 steps · CFG 4**, **1024×1024 빈 latent**에서
   네 컷을 한 이미지로 생성합니다. 작은 결과를 나중에 확대하는 방식이 아닙니다.
5. 좌상 → 우상 → 좌하 → 우하 순서로 각각 **512×512**를 자릅니다.
6. 원본과 컷을 한 DB 트랜잭션에서 저장하고 최대 4개 카드를 함께 연결합니다.
   문장이 바뀌었거나 사용자가 그림을 붙였으면 덮어쓰지 않고 `409 image_card_changed`로 중단합니다.

남은 카드가 1~3개면 나머지 칸은 흰색으로 비우도록 지시하고 실제 카드 수만큼만 자릅니다.
묶음마다 기준 인물이 3명 이내이면 6개는 4+2, 10개는 4+4+2입니다. 인물이 달라지면 더 작은 묶음으로 나눕니다.
한 카드 자체에 4명 이상이 필요하면 참조를 버리지 않고 해당 카드의 내용을 나누도록 안내합니다.
각 묶음에 필요한 고정 인물 원본을 다시 전달하지만 묶음 간 일관성은 보증하지 않습니다.
기존 단일 장면 프롬프트의 “한 장면만/시트 금지” 지시는 이 경로에서 완전히 교체합니다.
화풍 요구는 단순 애니메이션 이미지 또는 삽화이며 별도 분위기 샘플을 섞지 않습니다.
현재 [이지리드 규칙](EASY_READ.md)은 각 컷의 핵심 뜻 하나와 구체적인 단어 아이콘을 우선합니다.
배경과 보조 요소를 줄이며, 원문에 없는 상황을 그림으로 추가하지 않도록 지시합니다.

## 제한·검증 범위

- 묶음 전체의 기준 인물 **1~3명**이 필요합니다. 초과·누락은 유료 설계·제출 전에 거절하고 참조를 몰래 생략하지 않습니다.
- 프로젝트 100개·12MiB 한도는 **원본 시트와 모든 크롭**까지 합산합니다. 시트 다운로드는 최대 8MiB입니다.
  시작 전 개수 검사에도 예상 묶음 수만큼의 원본을 합산합니다. 실제 생성 바이트 크기는 저장 시 재확인합니다.
  고해상도 복잡한 그림으로 한도를 넘으면 원격 작업은 완료됐더라도 문서 적용이 실패할 수 있습니다.
- 반환 크기가 제출한 워크플로와 다르면 크롭·적용하지 않습니다. 업로드/기본 생성의 기존 축소 제한은 유지합니다.
- 이전 버전에서 이미 접수한 2048×2048 작업은 같은 원격 작업을 확인하고 원본을 1024×1024로 축소한 뒤 512×512로 자릅니다.
  접수 불확실 작업을 재제출하지 않으며, 확실히 미제출인 작업만 새 해상도로 컴파일합니다. 이미 저장한 그림은 바꾸지 않습니다.
  저장 한도는 그대로이며 해상도 축소만으로 모든 자료가 한도 안에 들어가는 것은 아닙니다.
- 컷 경계는 고정 중앙 분할입니다. AI가 배치를 어기거나 인물이 경계에 걸리면 잘못 잘릴 수 있습니다.
  자동 경계 추정·사후 재배치·자동 유료 보정은 없습니다.
- 얼굴/의상 유지, 네 장면의 의미, 주장과 확정 사실, 지급 명령과 완료 구분은 **원본+각 크롭을 제작자가 직접 대조**해야 합니다.
  alt/meaning도 설계 초안이고 실제 그림 검사 결과가 아닙니다. verified나 검토 완료를 자동 변경하지 않습니다.
- 자동화 테스트는 API 모의 응답으로 생성 연결·크롭·저장·재시도만 검증합니다. 모델 품질의 증거가 아닙니다.

## 실제 생성 테스트

OpenAI 및 Comfy 키와 `OPENAI_MODEL`을 환경변수로 준비합니다. 실제 키는 저장소에 넣지 않습니다.
설정한 `.env`는 Python에서 자동 로딩되지 않으므로 README의 로딩 방법을 먼저 사용합니다.

```sh
PYTHONPATH=. python scripts/test_storyboard_live.py --live
```

GPT 분석·초안·캐릭터 선택·4컷 설계 및 Comfy 생성 비용이 발생합니다. 별도 인물 외형 분석은 호출하지 않습니다.
테스트는 별도 임시 폴더의 로컬 SQLite를 사용하고 **운영 Turso와 기존 자료를 변경하지 않습니다**.
가상 임대차 예제에서 실제 생성한 초안의 첫 장면 카드 4개를 사용합니다. 카드가 부족하면 이야기를 지어내지 않고 중단합니다.
진행 로그에 나온 테스트 폴더에 `run.json`과 DB가 남습니다. 중단/오류 뒤 새 테스트를 시작하지 말고 같은 폴더로 이어 확인합니다.

```sh
PYTHONPATH=. python scripts/test_storyboard_live.py --live --resume /absolute/test/directory
```

완료 시 `sheet.png`, `panel-1.png`~`panel-4.png`, `document.json`을 저장합니다.
원본·크롭·카드 문장을 함께 보고 컷 순서, 인물 얼굴/옷, 핵심 행동, 잘림, 글그림 의미를 확인합니다.
실제 Cloud의 모델·노드·해상도 가용성은 preflight에서 점검하며 계정별 실실행이 필요합니다.
기존 편집 진입 API로도 동일하게 테스트할 수 있고 응답 계약은 바뀌지 않습니다.
운영 원본 시트 ID는 내부 `image_batch.storyboardSheets`에 남으며 `/api/studio/assets/{sheetId}`로 조회됩니다.
원본은 독자 문서에는 포함하지 않지만 기존 그림 URL처럼 주소를 아는 누구나 조회할 수 있습니다.

## 롤백

첫 4컷 실험을 반영하기 직전 BE main 기준 커밋은 `c87df47`입니다.
우선 아래 설정 롤백을 사용하고, 코드 전체를 되돌릴 때는 진행 중 원격 작업을 먼저 확인합니다.

`STUDIO_SCENE_MODE=single`로 되돌리고 서버를 재시작합니다.
Git 연동 Vercel 배포에서는 `vercel.json`의 해당 값을 `single`로 변경해 main에 푸시합니다.
대시보드만 변경하면 저장소 설정이 남으므로 Git 설정도 함께 되돌려야 합니다.

- **새 묶음**은 기존 카드별 생성으로 돌아갑니다. `assist/images`는 실험 전후 모두 기존 카드별 경로입니다.
- 아직 Comfy에 제출하지 않은 유휴 묶음은 예약을 해제하고 기존 경로로 돌아갑니다. 실행 중 lease가 남으면 먼저 끝날 때까지 예약을 유지합니다.
- 이미 접수했거나 접수 불확실한 묶음은 그대로 이어 확인합니다. 새 카드별 유료 작업으로 대체하지 않습니다.
  따라서 설정을 끈 직후 기존 묶음 한 번은 4컷으로 완료될 수 있습니다.
- 접수 불확실/실패 작업은 운영자가 작업 ID를 대조해야 합니다. 설정 변경이나 새로고침으로 유료 재제출하지 않습니다.
- 기존 카드 이미지와 원본은 삭제·교체하지 않습니다. 완료한 실험을 취소하려면 제작자가 장면을 직접 수정합니다.
- 그림 없음으로 일시 중단한 예약 묶음도 그림 설정을 다시 켜면 같은 작업을 이어 확인합니다.
  초안 재생성은 별도의 명시적인 새 제작 작업이며 자동 롤백 도구가 아닙니다.

실험은 `app/studio_storyboard.py`와 `StudioBatch`의 opt-in 분기에 격리돼 있습니다.
즉시 전면 구버전 배포가 필요하다면 먼저 시작한 원격 작업을 확인하세요. 그룹을 모르는 구버전 코드로 진행 작업을 처리하면 중복 생성 위험이 있습니다.
