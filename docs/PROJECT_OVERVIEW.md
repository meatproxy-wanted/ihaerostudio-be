# 이해로 스튜디오 · 현재 프로젝트 정리

기준: 현재 저장소의 구현. 설계 초안이나 대화에서 검토한 대안이 아니라 실제 등록된 API를 설명합니다.

## 목적

발달장애가 있는 성인을 존중하는 쉬운 판결 설명자료 제작 도구입니다.
AI 초안 이후 제작자가 해야 하는 원문 대조, 편집, 검토, 읽기·인쇄 자료 제작을 한곳에서 연결합니다.
법률 조언이나 공식 판결문 대체, AI 정확성 보장이 목적은 아닙니다.

프론트는 Next.js(`ihaerostudio-fe`), 백엔드는 FastAPI(`ihaerostudio-be`)입니다.
원문 분석·글 생성·문장 보조·캐릭터 선택·장면 설계는 GPT API를,
장면 이미지 생성은 Comfy Cloud의 Qwen 워크플로우를 사용합니다. Ollama는 사용하지 않습니다.

## 최초 화면 시안과 API 매핑

아래 경로 앞에는 `/api/studio`가 붙습니다. `{id}`는 프로젝트 ID입니다.

| 시안 단계 | 현재 구현 | 주요 API |
| --- | --- | --- |
| ① 판결문 업로드 | PDF 텍스트 추출 또는 텍스트 입력, 설정 및 사건 구조 분석·저장 | `POST /projects/pdf`, `POST /projects/text`, `PUT /projects/{id}/settings` |
| ② 사건 구조 확인 | 원문·당사자·주장·판단·결정 조회와 제작자 수정 | `GET /projects/{id}/source`, `GET/PUT /projects/{id}/structure` |
| ③ 쉬운 글·그림 편집 | 글 초안 생성, 편집 진입 시 그림 자동 준비·적용, 문장·용어 보조, 장면 변경·업로드, 문서 저장 | `POST /projects/{id}/document/generate`, `POST /projects/{id}/document/prepare-images`, `POST /projects/{id}/assist/...`, `GET/PUT /projects/{id}/document` |
| ④ 검토하기 | 세 가지 규칙 점검, 항목 확인/복원, 제작자 최종 체크리스트 | `POST /projects/{id}/review/run`, `/dismiss`, `/dismiss-all`, `/restore`, `/complete` |
| ⑤ 결과물 미리보기 | FE 읽기·인쇄 레이아웃. 게시본은 고정 스냅샷 | `GET /projects/{id}/document`, `GET/POST /projects/{id}/publications`, `GET /projects/{id}/publications/{publicationId}` |
| ⑥ 내보내기·공유 | FE 브라우저 PDF 인쇄와 게시본 읽기 화면 공개/해제 | `PUT /projects/{id}/public`, `GET /reader/{id}` |

시안의 모든 항목을 AI가 자동 판정하는 것은 아닙니다.
금액·관계·주장/판단·글그림 의미 확인은 아래 검토 경계를 따릅니다.
카드뉴스 PNG 다운로드와 영상 생성은 현재 제공하지 않습니다.

## 글과 그림이 만들어지는 순서

`document/generate`는 구조 확인을 마친 자료에서 글을 생성·저장합니다.
그림 준비는 별도 `document/prepare-images` 호출이며 현재 FE가 편집 진입 시 자동으로 이어 호출합니다.

1. GPT가 10종 가상 캐릭터 중 인물마다 서로 다른 하나를 선택합니다.
   선택 입력은 캐릭터 외형 설명과 partyId이며 실제 당사자 사진이나 외모 정보가 아닙니다.
2. 프로젝트 내부 `character_library.bindings`에 `partyId → characterId`를 저장합니다.
   배정한 캐릭터는 새로고침·추가 컷·동일 인물의 초안 재생성 시 다시 선택하지 않습니다.
   새 partyId가 추가되면 아직 쓰지 않은 캐릭터에서 추가 배정할 수 있습니다.
3. 선택 캐릭터의 기본 포즈에서 얼굴을 잘라 768×768 카드 자산으로 저장·자동 적용하고 인물 그림을 고정합니다.
4. 장면에서 필요한 인물을 partyId 및 문장·원문 근거의 이름/역할로 찾습니다.
   저장된 얼굴 자산의 내부 메타데이터를 확인하고 같은 캐릭터의 한 명짜리 기본 포즈 원본을 가져옵니다.
5. OpenAI가 레퍼런스 픽셀의 외형을 분석하고, 글·원문 근거를 바탕으로 장면 행동·관계·사물 상태와 대체텍스트를 설계합니다.
6. 서버가 Comfy 워크플로우 JSON을 만들고 Qwen-Image-Edit-2511에 원본 레퍼런스를 업로드합니다.
   40 steps·CFG 4이며 기본 정사각형 출력은 768×768입니다.
7. 결과 PNG를 DB에 보관하고 카드에 자동 연결합니다.

캐릭터셋의 시트에는 4포즈가 있지만 현재 레퍼런스로 쓰는 것은 첫 번째 기본 포즈 한 명입니다.
시트 전체·다른 포즈 3명·얼굴 크롭을 장면 레퍼런스로 보내지 않습니다.
고정 자산만 배치하는 장면 합성기는 아닙니다. 기본은 카드별 생성이며,
`STUDIO_SCENE_MODE=storyboard4`를 켜면 2048×2048의 2×2 이미지 한 장을 만들어 최대 4개의 1024×1024 컷으로 분할합니다.
이는 [롤백 가능한 실험](STORYBOARD_EXPERIMENT.md)이고 외형·컷 경계·상황 일치를 보증하지 않습니다.

## “자동”, “고정”, “수정”의 의미

- 자동: 사용자가 카드마다 생성·선택하지 않고 편집 진입 시 서버가 적용합니다.
  기본은 요청당 최대 카드 하나, 4컷 실험은 장면 최대 4개를 처리하므로 전체 생성은 여러 요청에 걸칩니다. 페이지를 닫은 뒤 자동으로 남은 카드를 계속 처리하는 작업자는 없습니다.
- 고정: 인물 배정과 적용된 인물 그림의 교체·삭제를 막습니다. 이것이 Qwen 장면 속 얼굴까지 픽셀 단위로 같다는 보장은 아닙니다.
- 수정: 글·장면 이미지·대체텍스트·용어·원문 근거는 편집할 수 있습니다. 인물 얼굴과 고정 인물 카드 삭제는 막습니다.
- 추가 컷: 새 카드 추가만으로 완료된 일괄 준비를 자동 재실행하지 않습니다.
  그 장면 카드에서 그림 후보 API를 요청·적용합니다. 관련 인물은 기존 배정을 재사용합니다.
- 초안 재생성: 기존 글·장면 편집을 새 초안으로 교체하지만 고정 인물 그림은 유지합니다.
  새로운 장면의 일괄 준비는 다시 시작합니다. 고정 인물을 빼거나 partyId를 바꾸면 오류가 날 수 있습니다.
- `source=library`: 기존 API의 자산 분류값입니다. 고정 캐릭터 얼굴뿐 아니라 AI 생성 장면도 이 값을 사용하므로 “10종 캐릭터 자산”이라는 뜻으로 해석하면 안 됩니다.

기존 자료의 적용·고정 인물과 미완료 유료 작업은 새 캐릭터셋으로 바꾸지 않습니다.
`STUDIO_CHARACTER_MODE=generate` 및 구형 호환 경로는 [그림 생성 상세](IMAGE_GENERATION.md)에서 별도로 설명합니다.

## 검토는 무엇을 확인하는가

자동 `review/run`은 외부 AI 호출 없이 다음만 점검합니다.

| 규칙 | 표시 | 의미 |
| --- | --- | --- |
| 문장에 원문 근거 없음 | required | 근거 연결 또는 제작자의 확인이 필요하며 미처리이면 검토 완료 불가 |
| 원문 전체에 없는 숫자 있음 | suggested | 금액·날짜·기간을 살펴보라는 안내. 수치·단위·관계의 정확성을 검증하지 않음 |
| 60자 초과 문장 | suggested | 문장 길이를 줄일지 확인. 어절 수나 UTF-16 길이가 아닌 서버 문자열 길이 기준 |

최종 체크리스트의 금액·관계·주장 구분, 그림 사용 시 글그림 의미는 제작자가 직접 확인합니다.
원문 위치 강조는 근거 연결이며, AI가 법적 의미나 그림의 정확성을 보증했다는 표시는 아닙니다.

## 저장과 공개

현재 실행 경로는 `main.py → studio_api.py`입니다. 사건·문서는 `studio_provider.py`와 `studio_domain.py`,
자동 그림 준비는 `studio_batch.py`, 캐릭터 선택·크롭은 `studio_library_selection.py`와 `studio_library.py`,
장면 생성은 `studio_generation.py → image_workflows.py → comfy.py`가 담당합니다.
`video_*`, `render.py` 등 구형 모듈이나 일부 Provider의 구형 문서 메서드는 현재 등록 API가 아닙니다.
파일이 존재한다는 이유로 영상·BE PDF 출력 기능이 제공된다고 해석하지 않습니다.

프로젝트 JSON: `studio_projects`.
이미지 바이너리: `studio_assets`.
캐릭터 선택·그림 생성·진행 상태: `studio_image_jobs`.
레퍼런스 외형 분석 캐시: `studio_character_appearances`.

제작자 문서는 저장 버전 충돌을 검사합니다. 게시본은 생성 당시의 내용·검토 상태를 고정한 스냅샷입니다.
게시본 생성과 공개는 별도 요청이며, 검토 완료 게시본만 공개할 수 있습니다.
독자 응답에는 원문 근거·검토 메모·작성 기록을 숨깁니다.

새 PDF의 원본은 저장하지 않지만 추출 텍스트는 저장합니다.
그림 URL은 인증 없이 조회할 수 있으므로 미공개 문서의 접근 통제와 다릅니다.
공개 해제는 독자 문서를 숨기지만 그림 URL을 폐기하지 않습니다. 자료 삭제도 soft delete입니다.

## 제한 및 검증 상태를 읽는 법

캐릭터 선택 후보는 10종이지만 자동 준비의 인물 상한은 6명, 장면 레퍼런스 상한은 3명입니다.
자료당 이미지 100개·12MiB 제한이며, 연결을 제거한 자산도 저장 용량에 남습니다.

단위·통합 테스트는 외부 AI를 모의 처리합니다. 캐릭터 이미지·크롭은 실제 자산으로 시각 검수합니다.
실제 Qwen 외형 유지·상황 정확성·속도·운영 계정 모델 가용성은 별도 실 생성 확인이 필요합니다.
Git main 반영, Vercel 빌드, 운영 배포, 실제 AI 생성 성공을 각각 구분해 기록합니다.
